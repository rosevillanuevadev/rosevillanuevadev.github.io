Two-tier instruction design for a documentation agent

Built by correctionTwo-tier instructions

An agent for building and auditing reference guides, built by correction rather than by specification: every fix made on a real guide became a rule in its instructions. The most transferable finding is not the guides. It is watching its own rules silently disappear across rewrites and diverging copies.

Project scope

An agent for building and auditing reference guides used by outsourced partner support teams. Those teams work from a separate set of guides and cannot open several internal sources, so a guide has to be researched from places the reader cannot reach and then written to stand on its own.

The guides had grown by topic over time. One topic alone had 31 pages. Someone handling a live interaction had to know which page applied and whether it was still current.

Constraints

Writing one guide is four separate jobs, and only one of them is writing:

  • Research across sources the reader cannot see.
  • A structure that works for an adult learner mid-interaction, not a reference index.
  • A scope decision on every step: what the reader can handle, investigate, or must escalate.
  • Wording that matches a house writing standard.

Every guide was built by hand, and the rules for doing it well lived in one person's practice rather than in anything written down.

Approach

The first brief set the audience, the tools the reader has, and a set of tone rules. After that, each guide was a working session, and every correction made during a guide was carried forward into the instructions. The agent was built by correction rather than by specification.

CorrectionRule it became
An inference presented as factEvery factual claim sourced, gaps flagged explicitly
The word "simple" in a step"simple", "easy" and "just" banned
A link to a source the reader cannot openUsed for accuracy, never linked
"response scripts"House terminology enforced
A 31-page topic flattened into one pageSubpages by subtopic, tools placed per subpage
A tester assumed a tracker issue was requiredMade optional, lookup request type added

Implementation

Two-tier instructions

When the hosted thread broke repeatedly under the weight of the instructions, they were moved into a dedicated agent and split into two tiers: a long file the agent reads for context, and a short checklist of rules it must verify before every response. The split exists because a rule buried in a long document is not a rule that gets applied under generation pressure.

Porting to a local skill

The port to a local agent framework removed the workarounds that existed only to survive thread limits, and added three things: live research tools, visuals embedded directly in the guide, and a publish step placed behind an explicit gate rather than run automatically.

Result

  • Published guides across six topics, including one parent page with eight subpages replacing a sprawling topic, and a five-page product suite.
  • Audits with neutral tracker comments for three topics, plus 40 working files and visuals.
  • Published setup: instructions, the checklist, a changelog and a README, so others can stand the agent up themselves.
  • A lead tested it and found a friction point, which was changed two days later. The documentation owner said it would make building guides faster and planned to use it.

What the failures taught, which is the part worth keeping

  • Rules can be lost when an agent rewrites its own instructions. A neutral-framing rule was added, then disappeared between two versions. It was raised again months later and saved outside the agent instead. The same happened to two other rules during the first rewrite.
  • Instructions maintained in several places drift apart. The published copy stopped being updated, and two working copies have diverged since. A bulk edit removed the title and role line from one copy only, and that went unnoticed for nearly three weeks.
  • The rules that lasted were the ones traceable to a single named correction on a real guide. Rules invented in the abstract did not survive.

The generalizable finding. An agent whose behavior lives in editable instructions has no mechanism preventing silent regression. Version control on the instruction file is not optional infrastructure, it is the only thing that makes the agent's behavior reproducible, and a single source of truth matters more than the quality of any individual rule.
