GPS track verification and gap detection

Live map Repository Straight-line comparison
JavaScript, GPXReusable, four swims

A reusable tool that takes a swimmer's actual GPS track after a swim and renders what was really swum, including the gaps where no swimming was recorded. Used for evidence review during ratification.

Project scope

A completed swim arrives as a set of GPX files, one per leg. For a multi-day attempt that can be dozens of files. Verifying the swim means answering one question: does the recorded track support the claimed distance?

Summing the files does not answer it. The support boat moves between sessions, so the raw total includes transit the swimmer never swam. And the files do not arrive in the order the legs happened.

Constraints

  • Works from whatever the swimmer supplies. No control over file naming, ordering or device.
  • Any exclusion has to be defensible to the swimmer, with coordinates, not just a smaller number.
  • Reusable across swims rather than rebuilt per applicant.

Approach

  1. Match legs by actual GPS position rather than filename order, since filenames are unreliable.
  2. Treat a discontinuity above a distance threshold as unrecorded, not as swum.
  3. Render the whole track so the reviewer sees the shape, not only the total.
  4. Report every exclusion with its coordinates so the swimmer can respond to specifics.

Implementation

Position matching

Legs are ordered by where they physically start and end rather than by file order. On one route, ordering by filename produced 24 apparent discontinuities. Ordering by position reduced that to 9. The other 15 were an artifact of how the files happened to be named.

Gap threshold

A separation above 300 meters between the end of one leg and the start of the next is treated as a gap, excluded from the total, and reported. Below that it is treated as GPS drift.

Applied per swim

Deployed for individual swims as a standalone page per attempt, so the reviewer and the swimmer are looking at the same rendering. The most visible application was a high-profile long distance swim in 2025.

Result

  • Distance claims are checked against the track rather than accepted from a summary.
  • Exclusions come with coordinates, so a swimmer can contest a specific gap rather than a number.
  • One tool applied across four swims instead of a fresh build each time.
