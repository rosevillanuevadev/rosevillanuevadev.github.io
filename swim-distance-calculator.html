Route distance calculator for open water swims with Python

Repository Methodology Forked router

Stack

Python 3searoute-py (forked)shapelypyprojnumpygpxpyglobal-land-maskFlaskpsycopg2PostgreSQLGoogle Maps JS APIRailway

A service that computes the shortest sea route between two coordinates without crossing land, for a swim that has not happened yet. It measures a planned route at approval time, before anyone gets in the water. It replaces unqualified great-circle distance, which is wrong for any route with land between its endpoints, and it produces a figure that can be recomputed and defended when a swimmer disputes it.

Project scope

Swim distances were being certified using straight-line distance between the start and finish coordinates. That number is only correct when the entire path is open water. For a crossing that must go around a headland, an island, or into a bay, it understates the real distance, and for a route measured point to point across a curving coast it can overstate it.

Circumnavigations had no method at all. Distances were produced by dragging a path around the landmass by hand and reading off the total. Two people doing that on the same island would not get the same number, and there was no record of where the path had been placed or why.

These figures are published, and they are contested. A record distance that cannot be reconstructed from its inputs cannot be defended.

Constraints

  • Any published figure has to be reproducible. Given the same inputs and the same recorded method, the number must come out the same.
  • No budget for commercial bathymetry or routing data.
  • The only viable open routing library, searoute-py, is built for commercial shipping. Its network has no coverage in narrow gulfs, inland seas or lakes, which is exactly where a lot of these swims happen.
  • The output has to be legible to a ratification committee, not only to me.

Approach

  1. Route over a maritime network instead of drawing a straight line, so the path avoids land by construction.
  2. Treat the router as unreliable. Validate every leg it returns against an independent calculation, and fall back deterministically when it fails.
  3. Decompose closed loops into legs between waypoints, so a circumnavigation is a sum of verifiable segments rather than one opaque number.
  4. Generate candidate waypoints automatically, but require a human to confirm each one before any distance is computed from them.
  5. Record the method used per leg, so the output states how it was derived rather than just what it came to.

Implementation

Leg validation

Every call to the router is checked against the haversine distance between the same two points before it is accepted. A leg is rejected and replaced with the straight-line calculation if any of the following hold:

ConditionWhat it catches
Distance is 0, or the path has one point or fewer Router found nothing and returned a degenerate result
Start or end of the returned path is more than 20 km from the requested coordinate Router snapped to a distant shipping lane instead of the actual point
Routed distance is more than 4× the haversine distance Router took a commercial detour, common in narrow gulfs

Each leg carries a method field recording whether it came from the router or the fallback, and the result includes a plain-language warning naming every leg that fell back and why. The total stays valid because an open water swim in an area with no sea lanes is measured as straight-line segments between waypoints anyway, but the reader is told which legs those were.

Waypoint confirmation gate

Waypoints for a circumnavigation are proposed by a model, which is fast but will occasionally place a point on land or inside a harbor wall. Those are not errors you catch by looking at a total.

So the proposal step and the calculation step are separate programs. The first renders every candidate as a numbered marker on a map for inspection. The second refuses to run unless the waypoint file has been renamed to mark it confirmed, and prompts for explicit confirmation if it has not: 

if "locked" not in wp_path.name:
    print("Warning: waypoints file name does not contain 'locked'.")
    print("  Run propose-waypoints.py first to verify waypoints.")
    confirm = input("  Continue anyway? (yes/no): ").strip().lower()
    if confirm != "yes":
        sys.exit(0)

The rename is the audit trail. A file called locked-manhattan-waypoints.json is a statement that a person looked at every point on a map.

Loop closure and assembly

The waypoint list is closed by appending the first point to the end, then walked pairwise. Distances are summed and the returned coordinate arrays are concatenated with the duplicate join point dropped at each boundary, producing one continuous polyline for rendering. Results are written as JSON with a UTC timestamp, the source waypoint filename, the per-leg breakdown and the waypoints used.

What gets stored

Every computed route is written to PostgreSQL, not just returned. Point to point swims go to one table, circumnavigations to another, each row holding the coordinates, the distance in kilometers and miles, any warning raised during validation, and the full path as JSON. Circumnavigation rows also keep the waypoints the route was built from.

Storing the path alongside the number is what makes the figure defensible later. A disputed distance can be pulled up and inspected as the geometry that produced it, rather than recalculated from scratch and hoped to match.

Result

Published distances are reproducible from their inputs, and the method used for each segment is part of the record. A reader can see which legs came from the router and which fell back, rather than being handed a single total.

Every run records the offshore buffer it was computed at, so a figure traces back to the named parameter that produced it and can be recomputed at a different setting during review. On one circumnavigation of roughly 1,500 km, that made the difference between two runs attributable to one recorded value.

Circumnavigation routes are stored with their waypoints and path, so a later attempt on the same island is measured against a recorded baseline rather than a fresh hand-drawn path.
